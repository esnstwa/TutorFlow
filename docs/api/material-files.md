# API учебных файлов

Контракт расширяет существующие `FileResource`, `Lesson.materials`, `Homework.attachments` и `HomeworkSubmission.attachments`. Новых таблиц и миграций схемы нет. Все маршруты зарегистрированы в существующем `app.web.router`; менять `app/main.py` или ученический router для подключения не требуется.

## Сессия и права

Используется существующая session cookie. Изменяющие запросы требуют существующий `X-CSRF-Token`; браузерный `session.js` уже добавляет его в same-origin fetch. Не передавать токен в URL и не сохранять файлы/приглашения в localStorage.

- Преподаватель загружает файлы от своего имени, изменяет/удаляет свои материалы и привязывает их только к своим занятиям/заданиям.
- Новый файл **приватный по умолчанию**. Само наличие ученика у преподавателя не даёт ему доступ ко всем файлам.
- Ученик читает свой файл либо файл своего преподавателя, явно прикреплённый к занятию этого ученика или к домашнему заданию, где он является получателем.
- Преподаватель также читает файл ученика, явно включённый в ответ на задание этого преподавателя. Произвольные несданные загрузки ученика ему не доступны.
- Чужие ответы не открываются другим получателям того же задания.
- Доступ проверяется заново на каждом запросе. Отвязка материала/удаление получателя отзывает соответствующее основание доступа. Если осталось другое разрешённое основание, доступ сохраняется.
- Архивирование карточки не уничтожает историю и само по себе не создаёт/не расширяет право доступа.
- Чужой и несуществующий объект возвращают одинаковый `404`. Без сессии — `401`; недопустимая роль или CSRF — `403`.

## Основные endpoints

| Метод и путь | Назначение | Доступ |
|---|---|---|
| `POST /api/files/upload` | Передать байты и создать материал; при необходимости сразу прикрепить | teacher + CSRF |
| `GET /api/files/{id}` | Общие безопасные метаданные | разрешённый teacher/student |
| `GET /api/files/{id}/download` | Скачать содержимое | разрешённый teacher/student |
| `GET /api/files/{id}/preview` | Безопасный inline-просмотр поддерживаемого содержимого | разрешённый teacher/student |
| `GET /api/materials` | Существующий список собственных материалов преподавателя | teacher |
| `GET /api/materials/{id}` | Существующие расширенные метаданные своего материала | teacher |
| `PATCH /api/materials/{id}` | Существующее изменение title/kind/description/url | teacher + CSRF |
| `DELETE /api/materials/{id}` | Удалить материал и связи, затем содержимое | teacher + CSRF |
| `POST /api/{resource}/{resource_id}/materials/{id}` | Существующая привязка | teacher + CSRF |
| `DELETE /api/{resource}/{resource_id}/materials/{id}` | Существующая отвязка | teacher + CSRF |

Для привязки `resource`: `lessons`, `homework` либо совместимый alias `assignments`. Обе стороны связи должны принадлежать текущему преподавателю. Привязка повторно не создаёт дубль отношения.

### Загрузка

Сохранён существующий протокол: тело — **сырые байты одного файла**, не JSON и не multipart. Браузер передаёт объект `File` как `body`.

Заголовки:

| Заголовок | Правило |
|---|---|
| `X-Filename` | Обязательное исходное имя без каталогов, `encodeURIComponent(file.name)` |
| `Content-Type` | Реальный заявленный MIME; неизвестный — `application/octet-stream` |
| `X-Title` | Необязательное название, URI-encoded UTF-8, 1–200 символов |
| `X-File-Kind` | Необязательная пользовательская категория, URI-encoded UTF-8, 1–80 символов; по умолчанию «Файл» |
| `X-CSRF-Token` | Существующий CSRF-токен сессии |

Без `X-Title` название выводится из исходного имени, до 200 символов; само `original_name` не обрезается. ASCII-имена без специальных символов совместимы с прежними клиентами. Некорректные percent escapes/UTF-8 и управляющие символы отклоняются, а не исправляются.

Необязательные query-параметры — положительные целые `lesson_id`, `homework_id`. Можно передать оба: создание файла и обеих связей фиксируется одной транзакцией БД. Чужая/отсутствующая цель отклоняется до чтения тела и повторно проверяется перед сохранением.

Пример браузерного запроса из teacher-кабинета, где загружен существующий session helper:

```js
const response = await fetch('/api/files/upload?lesson_id=123', {
  method: 'POST',
  headers: {
    'X-Filename': encodeURIComponent(file.name),
    'X-Title': encodeURIComponent(title),
    'Content-Type': file.type || 'application/octet-stream',
  },
  body: file,
});
const result = await response.json();
if (!response.ok || result.ok !== true) throw new Error(result.detail || 'Ошибка загрузки');
// Только result.file подтверждает сохранение; после ошибки проверить список перед повтором.
```

Успех: HTTP `200`, `{ "ok": true, "file": { ... } }`. Для обратной совместимости upload возвращает расширенный teacher DTO: прежние поля `id`, `title`, `kind`, `type`, `description`, `url`, `original_name`, `stored_name`, `path`, `mime_type`, `size`, `updated`, плюс безопасные действия/состояния и связи `lessons`, `homeworks`, `availability`. Эти внутренние поля не нужны ученическому интерфейсу: он использует общий metadata endpoint ниже, а не серверный путь.

Повторная отправка предотвращается single-flight состоянием teacher UI. Сервер не вводит скрытую дедупликацию: два самостоятельных успешных запроса создают два материала. При потере ответа нельзя считать запрос неисполненным — сначала перечитать список, особенно после `503`.

### Форматы и лимиты

| Расширение | Проверенный MIME | Preview |
|---|---|---|
| `.pdf` | `application/pdf` | нет; только download |
| `.png` | `image/png` | да |
| `.jpg`, `.jpeg` | `image/jpeg` | да |
| `.txt` | `text/plain`, корректный UTF-8 | да, только как текст |

Максимум — **20 MiB (20 971 520 байт)**. `FILE_UPLOAD_MAX_BYTES` позволяет установить меньший положительный предел, но не увеличить верхнюю границу. Тело читается по чанкам в скрытый staging-файл; фактическая квота действует и без Content-Length. Завышенный Content-Length отклоняется до чтения, несовпадение с фактической длиной — до создания записи.

Проверяются сигнатура, согласованность расширения/MIME и содержимое: PNG/JPEG проходят проверку структуры и декодирование, PDF — strict parsing с бюджетами объектов/страниц/распаковки, TXT — потоковую UTF-8 проверку. Одного расширения или заявленного MIME недостаточно. Пустые, повреждённые, анимированные изображения, зашифрованные PDF и PDF с известными активными конструкциями не принимаются. Лимит изображений — 16 млн пикселей и 16 384 по стороне; PDF — до 500 страниц. PDF с формами, активными действиями и внешними ссылками может быть отклонён как недопустимый.

SVG, HTML как активный формат, офисные документы, архивы и исполняемые файлы не входят в allowlist. Разметка внутри UTF-8 `.txt` остаётся обычным текстом. Проверка формата не является антивирусом или OS sandbox; жёсткий CPU/RSS timeout, общие дисковые квоты и rate limiting относятся к настройкам развёртывания.

Имена сохраняются только как метаданные. Путь к содержимому генерируется сервером; traversal, диски/ADS Windows, разделители, скрытые/reserved имена, NUL и управляющие символы отклоняются. Файл не размещается в public static directory.

### Общие метаданные для кабинета ученика

```json
{
  "ok": true,
  "file": {
    "id": 123,
    "title": "Рабочий лист",
    "kind": "Файл",
    "description": "",
    "original_name": "worksheet.txt",
    "mime_type": "text/plain",
    "size": 512,
    "has_file": true,
    "missing_file": false,
    "previewable": true,
    "download_url": "/api/files/123/download",
    "preview_url": "/api/files/123/preview"
  }
}
```

Пример иллюстрирует схему, не реальные пользовательские данные. Здесь нет `path`, `stored_name`, персональных данных других учеников или teacher-only связей. Все URL same-origin и не содержат токенов. Предыдущие JSON-записи/ссылки без содержимого имеют `has_file=false`, `download_url=null`, `preview_url=null`. При утрате содержимого запись сохраняется, `missing_file=true`; попытка чтения содержимого получает контролируемый `404`. `previewable` сообщает о поддерживаемой возможности, но endpoint дополнительно проверяет существование и фактический формат при чтении, в том числе для старых загрузок.

### Download и preview

Download всегда отдаёт `application/octet-stream`, `Content-Disposition: attachment` и UTF-8 filename по RFC 5987. Это безопасно и для прежних файлов с недостоверным MIME. Preview повторно валидирует формат и отдаёт только PNG/JPEG либо `text/plain; charset=utf-8` с `inline`; PDF — `415` даже владельцу.

Содержимое передаётся потоково, не через неограниченный byte array. Дескриптор закрывается в finally, включая разрыв ответа. Ответы содержимого: `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff`, CSP sandbox и `Cross-Origin-Resource-Policy: same-origin`. Общие метаданные и teacher metadata GET также запрещают shared caching. Range/resume не реализованы: GET возвращает полное содержимое; `Accept-Ranges: none`.

### Ошибки

Ошибки API имеют JSON с `detail`; значение — понятное сообщение, без SQL, stack trace и серверного пути.

| Код | Причина |
|---|---|
| `401` | Нет действующей сессии |
| `403` | Не та роль либо отсутствует/неверен CSRF |
| `404` | Объект/цель отсутствует или недоступен; содержимое утрачено |
| `413` | Превышена квота размера |
| `415` | Неподдерживаемый/подменённый формат; для preview доступен только download |
| `422` | Пустое/повреждённое содержимое, недопустимые имя/заголовки/ID, несовпадение длины |
| `503` | Ошибка хранилища или невозможность подтвердить транзакцию БД |

После `503` upload/delete сначала перечитать список: commit мог пройти, а подтверждение — потеряться. При ошибке БД файл удаляется только после независимой проверки, что он не связан с записью. Если БД недоступна для такой проверки, содержимое остаётся для последующей сверки, а не уничтожается на предположении об откате.

Успешное удаление: `{ "ok": true, "cleanup_pending": false }`. Если удаление записи подтверждено, но физическая очистка staging не удалась: `cleanup_pending=true`; файл уже недоступен через API, остаток требует обслуживающей сверки. DELETE сериализуется по существующей строке БД до staging. После ошибки backend возвращает `503`; восстановление staged содержимого возможно только после успешного rollback, под новой блокировкой и при подтверждённой актуальной ссылке той же записи. При неизвестном исходе commit, недоступной БД или исчезнувшей ссылке байты сохраняются скрытыми для сверки, а не безусловно возвращаются на исходное имя. Отсутствующий исходный файл при наличии его `.deleting` не считается завершённой очисткой: повторный DELETE возвращает `503` и сохраняет запись. Обычное отсутствие файла без staging и metadata-only записи по-прежнему допускают удаление. Конкурирующий DELETE может получить `404` после удаления строки первым запросом или безопасный `503` при конфликте/недоступности блокировки.

## Обратная совместимость и подключение кабинета ученика

1. Существующие student/homework ответы и их `attachments[].id` не меняются. Для каждого ID получать `GET /api/files/{id}` с существующей cookie.
2. Показывать title/original_name/size/MIME как текст. Не строить HTML из названия и не использовать серверные filesystem paths.
3. Download — обычная same-origin ссылка на `download_url`. Preview показывать только при непустом `preview_url`, открывать в новой вкладке с `rel="noopener"`; при 404/415/503 показывать ошибку, не фиктивный просмотр.
4. Не подменять URL на `attachment.url`: старое поле может описывать внешнюю ссылку, а не содержимое. Для защищённого файла использовать только общий endpoint.
5. `POST /api/files/upload` предназначен преподавателю и правильно возвращает ученику `403`.
6. Существующий `POST /api/student/files/upload` **не менялся** в рамках разделения ответственности. Его прежняя загрузка ответов не получает автоматически новые streaming/format гарантии. Для отдельной согласованной доработки Ксении: сохранить `get_current_student`/CSRF и `owner_id=student.user_id`, заменить `request.body()/store_bytes` общим `store_stream`, добавить те же ограничения заголовков/размера и безопасное подтверждение записи. Не расширять student-доступ до teacher-материалов по одному teacher_id. Ученический UI и защищённые router-файлы для A-04 не редактируются.
7. Существующие metadata-only API (`POST /api/materials`, legacy material create) остаются для записей/ссылок, но не заменяют upload. `POST /api/materials` больше не принимает клиентские filesystem paths/stored_name или ненулевой размер: такой запрос возвращает `422`, закрывая обход хранилища.

Постоянное хранилище, backup и безопасная сверка описаны в `docs/operations/material-storage.md`.
