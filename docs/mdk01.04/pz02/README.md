# ПЗ №2 МДК.01.04 — модульная архитектура и контракт

## Выбранный модуль

Выбран модуль проверки пароля `app/auth/passwords.py`. Он находится непосредственно на пути авторизации: потребитель `login` получает `PasswordVerifier` через FastAPI dependency injection и не знает о конкретном алгоритме хэширования. Это существующая бизнес-логика, а не учебная заглушка: от результата операции зависит выдача серверской сессии и доступ пользователя к TutorFlow.

Модуль выбран вместо выделения всей HTTP-регистрации, потому что граница проверки пароля уже имеет одну ответственность, наблюдаемый результат и безопасную замену зависимости без переписывания маршрута. Регистрация продолжает использовать существующий `create_user`; изменение ПЗ №2 не дублирует TTL-настройки PR #15.

## Ограничения доказательств

- До commit/push/tag версия сдачи не является неизменяемой: отчёт явно помечает её как рабочее дерево.
- `FixedPasswordVerifier` — тестовая подмена. Она подтверждает потребителя и границу контракта, но не исправность Argon2, БД или реального хэша.
- Р7 не отмечается выполненным без протокола другого студента.
- Изображения в отчёте должны быть получены из фактических исходников и команд; место для рисунка 6 остаётся помеченным как ожидающее независимой проверки.
