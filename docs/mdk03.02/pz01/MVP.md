# Границы MVP TutorFlow

## Основной сценарий → необходимые функции MVP

`Регистрация/вход → связь преподавателя с учеником → выдача задания → сдача → проверка/доработка → сохранённая история`

Необходимые функции: аккаунты и роли; серверная сессия; карточка ученика; одноразовое приглашение; ролевой и объектный доступ; одно задание с несколькими получателями; текстовая отправка; принять/вернуть; история попыток; постоянная БД.

## Baseline MVP

| Функция | Почему необходима |
|---|---|
| Регистрация, вход и выход | Без идентичности нельзя разделить данные двух ролей. |
| Роли преподавателя и ученика | Определяют разрешённые действия основного сценария. |
| Карточка ученика и одноразовая привязка | Создают проверяемую связь сторон без совпадения email «по догадке». |
| Создание `Homework` и получателей | Начало основной учебной цепочки; одно задание не дублируется. |
| Текстовая сдача работы | Минимальный способ передать результат без зависимости от файлов. |
| Принятие и возврат на доработку | Замыкают обратную связь и состояние работы. |
| Новая попытка вместо перезаписи | Сохраняет доказуемую историю взаимодействия. |
| Объектная авторизация, CSRF и постоянная БД | Без них сценарий небезопасен или теряет результат после перезапуска. |

## Reserve

| Функция | Почему может быть отложена |
|---|---|
| Календарь занятий и статусы оплаты | Полезен преподавателю, но цепочка задания работает без занятия. |
| Материалы и файлы | Текст покрывает минимальную выдачу и сдачу; нужна отдельная политика размера/хранения. |
| Поиск, фильтры и карточки статистики | Улучшают работу с объёмом, но не создают основную ценность при малом числе записей. |
| Google Calendar | Реальная интеграция ещё отсутствует; локальный календарь достаточен для MVP. |
| Диалоги и уведомления | Текущая реализация ограничена; статус задания уже передаёт минимальную обратную связь. |
| Автоматический email, recovery, подтверждение email | Важны для эксплуатации, но ручная ссылка позволяет проверить продуктовую цепочку. |
| Оценки, баллы, критерии, группы | Не нужны для базового «выдать — сдать — проверить» и требуют discovery. |

Reserve не объявляется ненужным: это управляемый объём после подтверждения Baseline MVP пользователями.
