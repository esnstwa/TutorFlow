Тестовая фикстура schedule_case создаёт новое SQLite :memory: с внешними ключами для каждого варианта. Дата фиксирована на 12.01.2035, Europe/Moscow. Два преподавателя, один аккаунт ученика и четыре карточки создаются через API с синтетическими данными example.com. У основного преподавателя есть активные Игорь и Павел, а карточка Антона архивируется; у второго преподавателя есть активный Денис. Для локального прогона личные данные и внешние службы не нужны. Фикстура подменяет получение БД, проверка сессии, роли и CSRF проходит через реальные зависимости. При тестовом HTTP настройки позволяют использовать cookie внутри TestClient.

| Набор | Вход |
|---|---|
| Допустимый | Свой активный ученик, 13.01.2035 10:00–11:00, «Оптика», заметка в 500 символов |
| Недопустимый | Конец равен началу или раньше, карточка чужая или архивная, пустая тема, неизвестный статус, заметка в 501 символ |
| Сессия / источник | Действующая cookie, варианты токена и источника из теста. Снимок всех столбцов lessons до и после читается новой сессией |
| Сохранение | После записи повторный запрос к детали и странице календаря; значения из строки сверяются отдельной ORM-сессией |

## Пять ответов по п. 4.6 методички

1. Защищаем карточки учеников, время, тему, ссылки, заметки и историю занятий, связи с учебными материалами, идентификаторы и данные сессий. Источники: [Lesson](../../../app/models.py), [проекция расписания](../../../app/schedule/calendar.py).
2. Недоверенный ввод приходит из JSON форм, параметров URL, ID объектов, cookie и HTTP-заголовков. Проверки: [lesson_values и scoped_lesson](../../../app/services.py), [маршруты расписания](../../../app/web/router.py), [проверка источника и токена](../../../app/auth/csrf.py).
3. Создавать занятие для своей активной карточки и изменять свои занятия может преподаватель со своей сессией. Для изменения действует защита запроса. Роль и сессия проверяются в [core/auth.py](../../../app/core/auth.py), объектная принадлежность — в [services.py](../../../app/services.py).
4. Ошибка может раскрыть частное расписание или заметки, добавить ложное занятие, сдвинуть время, отменить или удалить запись и потерять связь с учебным заданием. Ограничения времени и статуса находятся в [модели Lesson](../../../app/models.py), тест изоляции и регрессия удаления — в [test_teacher_schedule.py](../../../tests/test_teacher_schedule.py).
5. Конфигурационные секреты задаются средой или локальным .env вне Git, в CI — средствами управления секретами. Сессионный токен хранится на сервере как хэш, CSRF привязан к серверной сессии. В журнал и учебные материалы не выводятся исходные пароли, cookie, токены, строка подключения с credentials, ссылки приглашений и личные записи. См. [регламент](ENGINEERING_PROCESS.md), [хранилище сессий](../../../app/auth/sessions.py) и [настройки](../../../app/core/config.py).

Проверка через TestClient подтверждает бизнес-правила, HTTP-контракт и состояние SQLite после транзакции. Для PostgreSQL и миграций используется отдельный job Quality Gate. В этом прогоне не проверяются процессы с постоянной БД, конкурентное бронирование и пользовательский браузер.
